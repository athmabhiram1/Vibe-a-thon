## 2. Product / Synapse facts (confirmed)

### What Synapse claims to be
- **"Synapse is an enterprise context engine: a knowledge layer that reads what a business already runs and turns it into context AI agents can invoke, through one standard MCP interface."**
  - Source: https://2ndbrainlabs.ai/synapse
- **The pain ("integration tax"):** "Every source needs its own connection. Engineering teams write and maintain an adapter for each one. Delivery slows, costs rise and the agents still cannot reach most of what they need."
  - Source: https://2ndbrainlabs.ai/synapse
- **Core promise:** "Nothing is migrated or rebuilt" / "Systems stay in place, and teams choose what agents reach."
  - Sources: https://2ndbrainlabs.ai/ ; https://2ndbrainlabs.ai/synapse
- **Origin story (company's version):** "Synapse began with a single customer. A Tier 1 automotive supplier wanted AI to work with the enterprise systems that run its business. We built MCP servers for those systems by hand... Synapse is our answer" to doing it without months of manual effort.
  - Source: https://2ndbrainlabs.ai/about — **customer is anonymized; no name, logo, or verifiable case study found.**

### How it works (company's 4 steps)
1. Read (from source code or API endpoints), 2. Select (teams choose endpoints), 3. Generate (MCP server), 4. Run (where the team runs it).
- Source: https://2ndbrainlabs.ai/

### Three knowledge layers (company framing, from founder's Palantir-comparison essay)
- **Systems → MCP servers** (reads codebases/APIs, generates production-ready MCP servers). **Documents → Agentic RAG Pipelines** ("being built"). **Workflows → Skills** ("being built... to capture [approvals/escalations] so an agent can follow it").
  - Source: https://2ndbrainlabs.ai/blog/synapse-vs-palantir (Praveen Yalavarty, published 4 Aug 2026)
- **Governance:** "governance... at the source, not at the consumer" via security tokens scoped to MCP servers/RAG pipelines/Skills; per-tenant isolation; Enterprise tier runs inside customer cloud.
  - Sources: https://2ndbrainlabs.ai/blog/synapse-vs-palantir ; https://2ndbrainlabs.ai/ ("How Synapse secures")

### Synapse CLI (the hackathon-relevant artefact)
- **Package:** `@2ndbrainlabs-ai/synapse-cli` — "Agentic MCP server generator — the first piece of Synapse's Enterprise Context Engine."
  - Source: https://www.npmjs.com/~2ndbrainlabs-product (publisher page); full README at https://www.npmjs.com/package/@2ndbrainlabs-ai/synapse-cli
- **Install:** `npm install -g @2ndbrainlabs-ai/synapse-cli`, requires Node.js 20+, `synapse init` then `synapse build`.
  - Source: npm README (above) and console docs https://synapse.2ndbrainlabs.ai/
- **Open source:** "synapse-cli is now 100% open source — analyze, build, and deploy context engines for any AI host." GitHub org `2ndbrainlabs-ai`, repo `synapse-cli-ts` (TypeScript CLI), Apache-2.0, CONTRIBUTING.md / Code of Conduct / Security Policy published.
  - Sources: https://www.2ndbrainlabs.ai/products (note: www subdomain 308-redirects; canonical https://2ndbrainlabs.ai/products); https://github.com/2ndbrainlabs-ai/synapse-cli-ts ; https://github.com/2ndbrainlabs-ai/synapse-cli-ts/blob/main/CONTRIBUTING.md ; LinkedIn open-source announcement https://www.linkedin.com/posts/2nd-brain-labs_synapse-2ndbrainlabs-opensource-activity-7495488824823726080-EUa9

- **What it does technically:** client-side tree-sitter scan (language detection + route/function extraction); hosted generation via streaming gRPC backend OR fully local generation with user's own model (`--local` + `synapse model set anthropic|openai|groq|grok|openrouter|ollama|bedrock|vertex|custom).

- **Build modes:** Auto (expose HTTP routes as tools calling deployed API; hosted output = server config served by `@2ndbrainlabs-ai/synapse-mcp` runner, no file written) vs Custom (compose internal functions into one MCP tool; writes `<tool_name>_server.py`).
  - Source: npm README table "Build modes (Auto and Custom)"
- **Language coverage (verified from README):** Auto reads 6 — Python, TypeScript (.ts/.tsx), Java, C#, Go, Rust. Custom reads Python only. **All generated server files are Python. Plain JavaScript (.js/.jsx) is NOT scanned.**
  - Source: npm README
- **Pricing/tiers:** Developer (open source, free) / Hosted (MCP servers + console in 2BL cloud) / Enterprise (licensed inside customer cloud).
  - Source: https://2ndbrainlabs.ai/synapse
- **Free-tier limits:** 10 MCP servers + 100,000 indexed lines (`synapse info` shows usage).
  - Source: npm README

## 4. Strategic read (INFERENCE — clearly separated from facts)

What this company is likely to reward, given its positioning:

1. **Synapse CLI front-and-center.** The CLI is their only generally-available, open-source artefact and the stated build material ("build with Synapse"). A submission that does not actually run `synapse build` / ship an MCP server will read as off-brief. Show the `synapse build` output, the server-ID/config, and the MCP client wiring (Claude/Cursor/Copilot).
2. **An enterprise-system pain, not a toy demo.** Their whole narrative is "integration tax," legacy APIs, brownfield systems. Frame the problem as: real system(s) of record → exposed as governed MCP tools → agent does operational work *against live data*. Echo their language ("nothing migrated," "where it already lives") without parroting it.
3. **Live/operational, not lake/batch.** Their Palantir and data-lake essays argue operational AI should reach systems of record in real time. A demo that queries live endpoints (inventory/order/ticket-style, like their own examples: "order lookup, ticket creation, shipment tracking" — https://synaps3.ai/usecases via search snippet) and acts (read + write path) will resonate more than analytics dashboards.
4. **Governance story.** They govern "at the source" (scoped tokens, team select what agents reach, tenant isolation). Show endpoint selection, redacted secrets (`${ENV}` placeholders), and what the agent is *not* allowed to touch.
5. **Engineering credibility signals.** They publish changelogs ("Every release lists what it changed, in the changelog on GitHub" — https://2ndbrainlabs.ai/), run tree-sitter/AST extraction, stream over gRPC, and court open-source contributors. Clean repo, reproducible `synapse build --auto/--custom` steps, pinned models, and a PR/docs touch will be noticed. Note their constraint honestly if hit (e.g., "Custom reads Python only; generated servers are Python" — judges will know).
6. **Community-visible contribution.** Synapse Stars explicitly rewards Build/Create/Connect/Enable/Organize/Shape with progression Pulse→Nova and internships. A submission paired with a tutorial/video, docs improvement, or shared MCP server template serves both the hackathon and their community pipeline.
7. **Avoid claiming what they don't claim.** Don't name-drop customers, funding, or "winners from last year" — none are public. Don't pitch "rip-and-replace" or a new ontology/model-first platform; that is literally the architecture they argue against.
