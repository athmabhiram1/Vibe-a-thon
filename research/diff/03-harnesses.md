# 03 — Agent Harnesses vs Our Synapse + FastMCP Copilot

**Date:** 2026-11-22 · **Question:** for Track 3 ("copilot across two systems", live `--discover` update), should we stay on Synapse-generated FastMCP servers + a thin copilot agent, or adopt LangGraph / CrewAI / AutoGen / Claude Agent SDK / OpenAI Agents SDK / LlamaIndex / Haystack?
**Our baseline (from `research/03-synapse-technical.md` + `guide.txt`):** two codebases → two Synapse builds (Auto; Custom optional) → two MCP servers (hosted `npx synapse-mcp` runner *or* local `synapse_auto_server.py` / `<tool>_server.py`) → one copilot agent (any MCP client: Claude Desktop / Cursor / hand-rolled Python) that fans out across both, plus `synapse build --discover` live-update demo. Synapse itself has **no approval gate, no audit log, no idempotency** — all of that lives in the copilot/MCP layer we write (FastMCP middleware).

## 1. How approval gates actually work (verified)

### LangGraph — `interrupt()` + `Command(resume=)` + checkpointer
- In a node call `interrupt(value)` exactly once; it raises `GraphInterrupt`, persists state via checkpointer (`thread_id` required), surfaces payload to client. Resume with `Command(resume=<human decision>)`; node body **re-executes** from the top, resume values matched by call order. Docs: `docs.langchain.com/oss/python/langgraph/interrupts`, `.../concepts/human-in-the-loop`; Context7 `/langchain-ai/langgraph` `types.py` confirms checkpointer requirement + re-execution semantics.
- Production pattern: `interrupt_on` allowlist (Deep Agents) — pause only before nominated tool calls; reviewer can approve/edit/reject; rejection-aware routing cuts loopback ~40% (TURION 2026 analysis via niteagent/sobalabs).
- Strength: durable (survives process restart, days-long waits), time-travel debug, LangSmith trace. Cost: must wire checkpointer (SQLite/Postgres) + `thread_id` plumbing; every interruptible node must be idempotent on re-execution.

### CrewAI — three overlapping mechanisms
1. **Task-level:** `human_input=True` on a `Task` (classic crews) — console prompt per task execution.
2. **Flow-level:** `@human_feedback(message, emit=[approved/rejected/needs_revision], llm, default_outcome)` decorator on Flow methods (v1.8+/v1.15.x docs). Emits router events; listeners handle `@listen("approved")` etc. `HumanFeedbackResult{output, feedback, outcome, timestamp}`; `learn=True` distills lessons for pre-review. Verified in `crewai/flow/human_feedback.py` via gh_grep.
3. **Enterprise:** `@human_feedback` + Temporal-style durable flows, email-first approvals, UI components (CopilotKit), `hoop.dev` external policy pause.
- Gotcha: console HITL blocks; durable HITL needs Enterprise/Temporal plumbing. Audit via `human_feedback_history` / `last_human_feedback` on Flow runtime + Confident AI tracing integration.

### AutoGen (now in maintenance → Microsoft Agent Framework 1.0, Apr 2026)
- **AgentChat:** `human_input_mode` (`ALWAYS`/`NEVER`/`TERMINATE`) + `human_input` callback — functional approve/reject but terminal-blocking by design ("use only for short interactions").
- **Core:** `InterventionHandler` / `tool_agent_caller_loop` cookbook — intercept `before_tool`, prompt `Approve [y/N]`, return denial string as tool result. Community `n4n.ai` wrappers show the canonical 10-line decorator pattern.
- Status risk: AutoGen → maintenance mode; migration guide points to Agent Framework. Don't bet a hackathon on it unless reusing existing code.

### Claude Agent SDK (Anthropic harness around Claude Code)
- Two-level permissions: **rules** (allow/ask/deny, path-scoped) evaluated in fixed order — hooks → deny rules → ask rules → permission mode → allow rules → `canUseTool` callback — plus **modes** (`default`/`acceptEdits`/`plan`/`dontAsk`/`auto` with classifier). `canUseTool` + `PermissionRequest`/`PermissionDenied` hook events enable custom approvers. Hooks: `PreToolUse/PostToolUse/UserPromptSubmit/SessionStart` etc. (docs: `code.claude.com/docs/en/agent-sdk/permissions`, `/approvals`, `docs.claude.com/en/api/agent-sdk/hooks`).
- Multi-agent: subagents + compaction built in; MCP tools first-class. Audit = hook event log you persist yourself; no built-in ledger.
- Judge friction: needs Anthropic key + Claude subscription semantics; `dontAsk` vs `auto` confusion is a known footgun.

### OpenAI Agents SDK (`needs_approval` + `RunState` pause/resume)
- Per-tool `needs_approval: bool | (run_context, tool_params, call_id) -> bool` (sync or async). Guardrails split: `InputGuardrail` (policy reject) vs approval (pause). When tripped, run returns `interruptions`; convert to `RunState` via `to_state()`, call `state.approve(item)` / `state.reject(item)`, resume with `Runner.run(agent, state)`. Approval decision is cached in `RunContextWrapper` so re-runs don't re-prompt. Code verified via gh_grep: `src/agents/tool.py` (`needs_approval` field), `src/agents/util/_approvals.py` (`evaluate_needs_approval_setting`), `src/agents/run_internal/tool_actions.py`. Docs: `openai.github.io/openai-agents-python/human_in_the_loop`, `.../guides/human-in-the-loop` (JS), `ref/run_state`.
- Known bug (2026): approval not honoured on resume when `Runner.run` given a context (#4244); `stop_at_tool_names` can silently drop `add_input` (#5339). Workaround: resume with stored `RunState`, not fresh input.

### LlamaIndex — `AgentWorkflow` + interrupts + CopilotKit HITL
- `AgentWorkflow` (successor to ReAct/Router agents): event-driven multi-step orchestration; HITL via `interrupt()`-style human-request events surfaced through CopilotKit (`docs/.../llamaindex/human-in-the-loop.mdx`, `theneuralbase` course). `create-llama` `llama-index-server/examples/hitl` shows CLI-confirm pattern. Callback serialises proposed action → reviewer queue/webhook/UI → blocks until approval.
- Strength: best-in-class retrieval grounding (vector + knowledge-graph) if copilot needs docs/RAG; weakness: HITL is thinner than LangGraph/OpenAI SDK, mostly UI-callback shaped.

### Haystack — `ConfirmationHook` + `before_tool`
- `Agent(hooks={"before_tool": [ConfirmationHook(strategies={"tool_name": strategy})]})` with `BlockingConfirmationStrategy(confirmation_policy=AlwaysAskPolicy()|custom, confirmation_ui=SimpleConsoleUI()|RichConsoleUI())`. Human can **confirm / reject / modify params**. Custom `ConfirmationPolicy.should_ask() + update_after_confirmation()` (e.g. ask-once-per-tool). Docs: `docs.haystack.deepset.ai/docs/human-in-the-loop`, tutorial #47. Verified pattern; Redis-backed variant for Hayhooks + Open WebUI (non-blocking).
- Narrowest scope: tool-call confirmation only, no graph-level pause/resume. Great for RAG-pipeline teams already on Haystack; not a general orchestrator.

### FastMCP (our substrate — PrefectHQ, ~28.7k★, Apache-2.0)
- No native "approval gate" primitive. You build it with **middleware**: `on_call_tool` intercept → `AuthMiddleware(auth=callable)` for RBAC, `ApiKeyAuth` / OAuth (`GitHubProvider`, Entra/Google via Gateway), `Eunomia` policy file; **audit** via `AuditMiddleware.on_call_tool` emitting `{tool, call_id, schema_hash, redacted args, status, duration_ms}` (official `docs/servers/middleware.mdx`, Context7 `/prefecthq/fastmcp`). Enterprise Gateway adds SSO, per-tool RBAC, audit logs, SIEM export.
- Implication: our copilot must implement its own confirm-before-side-effect (MCP client-side prompt, or a `confirm_tool` wrapper tool, or FastMCP middleware that pends). ~20 lines; full control, zero magic.

## 3. Verdict for Track 3

1. **Stay on Synapse + FastMCP; do NOT swap harnesses.** Track 3 is graded on *two real systems combined + live `--discover` update* — Synapse owns that (same server id, delta re-parse, snippet still works). Every alternative harness still needs the two MCP servers anyway; swapping only adds key/dependency burden on judge laptops with zero judging credit.
2. **Steal exactly one idea: OpenAI-style `needs_approval` callable.** Implement a 20-line copilot policy — `needs_approval(tool, args) -> bool` (e.g. reads mutating, refunds/status changes, cross-system writes always ask; pure reads never) — plus a FastMCP `AuditMiddleware` JSONL log (`approval_id, approver, timestamp, tool, redacted args, outcome`). That satisfies Track 2's "confirmation before mutation" language judges look for, and gives you a 12-field audit record (permit.io schema) to show on screen.
3. **If the team insists on a harness** (e.g. to impress on "agentic" depth): pick **OpenAI Agents SDK** for the copilot loop (cleanest approval API, run-wide, serialisable `RunState`) *over* LangGraph unless you need multi-day durable waits — LangGraph's power (checkpoint/time-travel) is overkill for a 5-minute demo and its re-execution semantics create double-POST risk with Synapse's dumb HTTP-forward tools. Avoid AutoGen (maintenance mode), CrewAI Enterprise gates (won't run offline), Claude SDK (key friction).
4. **Demo script that wins:** Q1 spans both systems (e.g. "delayed shipment → affected customers → open tickets") with read-only tools (no prompt); Q2 triggers a write (e.g. "draft + file the escalation") → visible approval pause → approve → audit row appears; then `synapse build --discover` on a newly added endpoint → immediate reuse. That hits every rubric line (correct join, real use case, clean update) plus safety/audit bonus.
