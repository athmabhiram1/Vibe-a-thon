# 03 — Database Pick: Kill Postgres-First, Ship SQLite-Only (WAL)

**Verdict: Postgres is overkill for solo hackathon demo. SQLite-only (WAL + `better-sqlite3` / `node:sqlite`) ships faster, safer, and survives offline judge reruns. No Postgres fallback, no Supabase/Neon dependency, no in-memory primary.**

## Why Postgres-first + SQLite fallback loses

1. **Dual-dialect tax:** `SERIAL` vs `INTEGER PK AUTOINCREMENT`, `$1` vs `?`, `RETURNING`, `gen_random_uuid()` vs `strftime`, timestamp handling — every query needs 2 versions or a leaky abstraction. Solo dev can't afford this in 24–48h.
2. **Docker + fallback = two failure modes:** PG container won't boot (port clash, volume perms, ARM vs x86) *and* fallback sync drift. Debugging DB routing mid-demo is how demos die.
3. **Unused power:** PG wins on multi-writer concurrency, replication, JSONB/PostGIS/pgvector at scale. Demo workload = 1 writer, <10k rows, read-heavy — SQLite WAL wins outright on latency (no socket) per 2026 CISO-Assistant benchmark.
4. **Seed budget:** PG cold boot alone eats the <5s budget; SQLite seeds inside the budget with headroom for UI polish.

## Why not Supabase/Neon?

- **Cold starts are judge-visible:** Neon scale-to-zero 300–500ms typical, 600–980ms profiled, 12s on free tier. Supabase paid = always-on ($25/mo) to avoid it; free pauses after 7d inactivity.
- **No offline:** needs internet + valid `DATABASE_URL`. Expired token / revoked key / region outage = zero demo.
- **Judge rerun impossible** without sharing secrets. Violates "clone → `npm i` → run" rule.

## Why not in-memory primary?

- `:memory:` deleted when last connection closes; `cache=shared` only survives within one process. Restart = full re-seed, no post-demo inspection.
- No WAL file, no snapshot to `cp`. Good *only* for unit tests (`vitest` per-test DB), never as demo source of truth.
- Correct pattern: file-backed `app.db` for demo + `:memory:` for tests, same SQL.

## Ship-it recipe (SQLite-only)

```sql
PRAGMA journal_mode = WAL;
PRAGMA synchronous = NORMAL;
PRAGMA busy_timeout = 5000;
PRAGMA foreign_keys = ON;

CREATE TABLE idempotency_keys(
  key TEXT PRIMARY KEY,
  created_at TEXT DEFAULT (strftime('%Y-%m-%dT%H:%M:%fZ','now'))
);
CREATE UNIQUE INDEX ux_orders_active ON orders(customer_id) WHERE deleted_at IS NULL;
```

```js
// seed.js — single TX, <5s
db.exec('BEGIN IMMEDIATE');
for (const row of seedRows) stmt.run(row);
db.exec('COMMIT');
db.exec("VACUUM INTO 'seed-snapshot.db'");
```

```bash
# reset — ms, offline, judge-proof
cp seed-snapshot.db app.db
npm start
```

- Driver: `better-sqlite3` (sync, 1-writer pool) or Node 22 `node:sqlite`. No ORM needed; if ORM, use `drizzle-orm/better-sqlite3`.
- Keep `seed-snapshot.db` in repo (<5 MB). Add `demo:reset` script.
- Migrate to PG *only* if you win and need multi-user concurrency — `pgloader` / Drizzle migrate handles it post-hackathon.
